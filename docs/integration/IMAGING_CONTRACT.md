# Imaging contract — R2 preparation

`POST /v1/imaging/analyze` is a metadata-only, synthetic development boundary. It accepts a study identifier, modality, content type, SHA-256 digest, dimensions, task, and application profile. It never accepts image bytes, URLs, local paths, DICOM payloads, or raw patient data.

Supported task labels are `quality_check`, `segmentation_draft`, and `report_draft`. Without a validated model or typed draft inputs, the current implementation deliberately returns `ABSTAINED` with `findings: []` and `clinical_use_authorized: false`. This creates a stable integration point for MONAI, MedSAM2, nnU-Net, MedRAX, or an OHIF-AI adapter without implying that an unvalidated model output is a clinical finding.

When synthetic typed observations are supplied, the contract can compose an original report draft with evidence references and an explicit draft-only impression. When point, box, scribble, or text prompts are supplied, it can create a reviewable segmentation job with no mask reference until a validated adapter produces one. This mirrors useful imaging-workstation interaction patterns while keeping model execution outside the core API boundary.

Future adapters must provide:

- modality and image-quality checks before inference;
- de-identification and content-hash verification;
- model and weight provenance;
- structured findings or mask references with source coordinates;
- explicit uncertainty/abstention behavior;
- clinician review and sign-off;
- subgroup and modality-specific evaluation evidence.

The synthetic E2E evidence is generated by `apps/api/scripts/run_imaging_contract_e2e.py` and does not prove diagnostic performance.
